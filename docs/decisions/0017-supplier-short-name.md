# ADR-0017: Короткое имя поставщика для компактных таблиц

Статус: Предложено

## Контекст

Экран "Сравнение цен" (`/projects/:id/comparison`, ADR-0016) выводит по
одной колонке на каждого поставщика, у которого есть цена или ответ по
материалам проекта. Полные названия поставщиков ("Aluminum Distributors
Int LLC") делают шапку таблицы широкой и вынуждают либо горизонтальную
прокрутку раньше, чем нужно по объёму данных, либо перенос текста в
несколько строк в `<th>`, что ломает выравнивание с остальными
заголовками. Пользователь явно попросил компактную шапку и явно выбрал
способ — ручной ввод сокращения, а не автоматическую генерацию (обрезка
по CSS + tooltip рассматривалась и отклонена: она не решает саму
проблему ширины колонки, только прячет её за наведением).

## Решение

### 1. Новое поле `Supplier.short_name`, nullable, свободный текст

```python
short_name: Mapped[str | None] = mapped_column(String(50))
```

Заполняется вручную на карточке `/suppliers/:id`, как и остальные
справочные поля из ADR-0010 (`website`, `status`, `payment_terms` и
т.д.) — тот же паттерн: nullable, без автоматического заполнения или
миграции существующих данных, вводится постепенно по мере необходимости.

Ограничение длины `String(50)` — сокращение по определению короткое;
это защита от опечатки "вставил полное имя вместо сокращения", а не
содержательное бизнес-ограничение.

**Без валидации на уникальность.** `short_name` — подсказка для
быстрого визуального сканирования таблицы, не идентификатор (уникальность
уже обеспечена `Supplier.id`). Два поставщика с одинаковым или похожим
сокращением — не ошибка данных, которую нужно блокировать на уровне
API; в редком случае коллизии пользователь увидит два одинаковых
заголовка колонки и поймёт по данным в колонках, что это разные
поставщики (полное имя всегда доступно по `title`-тултипу, см. п.3).

### 2. Граница с ILP-солвером — то же разграничение, что ADR-0010 §3

`short_name` — чисто отображаемое поле, как и все поля из ADR-0010. Не
читается солвером (ADR-0002), не участвует в матчинге/агрегации,
никак не влияет на allocation. Фиксируется явно по той же причине, что
и в ADR-0010: чтобы не появилось искушения потом использовать
"короткое имя" как ключ группировки или сравнения где-то в расчётах.

### 3. Единственное место использования — шапка таблиц `PriceComparisonPage`

`short_name` подставляется **только** в заголовки колонок обеих таблиц
("План" и "Ответы поставщиков") на экране сравнения цен:
`supplier.short_name ?? supplier.supplier_name` — при отсутствии
сокращения используется полное имя, поле не обязательно к заполнению.
Полное имя остаётся доступным через `title`-атрибут на `<th>` (наведение
курсора), чтобы сокращение можно было расшифровать не уходя со страницы.

**Явно не в объёме:** замена отображения `Supplier.name` на
`short_name` где-либо ещё в приложении — `SuppliersPage`, `OrderDetailPage`,
`AllocationResultPage`, `PurchaseRecordsPage` продолжают показывать
полное `name`, как и сейчас. Проблема ширины колонки специфична для
матрицы "материалы × поставщики"; в остальных экранах поставщик
упоминается один раз на карточку/строку, где полное имя не создаёт
того же тесноты. Расширение на другие экраны — отдельное решение по
мере необходимости, не предполагается автоматически этим ADR.

### 4. UI ввода — на карточке `/suppliers/:id`, рядом с "Название"

Поле "Короткое имя" добавляется в форму `BasicInfoSection`
(`SupplierDetailPage.tsx`) сразу после "Название", с placeholder-примером
("ADI LLC"), без явной подсказки о лимите символов в интерфейсе —
браузерный `maxLength` на инпуте молча ограничивает ввод, отдельная
текстовая подсказка избыточна для поля с таким узким назначением.

**Отклонено: добавление поля в короткую форму создания поставщика
(`SupplierForm.tsx` на `/suppliers`).** Отклонено по аналогии с
ADR-0010 §4 — форма создания намеренно осталась минимальной (name +
delivery_policy), детали заполняются на карточке после создания;
`short_name` не исключение, это ещё один справочный атрибут, а не
обязательное при создании поле.

## Альтернативы

- **CSS `text-overflow: ellipsis` + `title`-tooltip на полном имени,
  без нового поля.** Рассмотрено первым, отклонено пользователем явно:
  не решает ширину колонки как таковую (обрезанный текст всё равно
  занимает то же место, что и без обрезки, если не выставить
  агрессивный `max-width`, из-за которого сокращённый текст станет
  нечитаемым без наведения на каждую колонку) и не даёт человеку
  контроля над тем, как именно называется сокращение — не то же самое,
  что осмысленная аббревиатура, которую человек знает и узнаёт с
  первого взгляда.
- **Автоматическая генерация аббревиатуры программно** (например, по
  заглавным буквам слов названия). Отклонено — даёт нечитаемые или
  неоднозначные результаты для реальных названий поставщиков (тот же
  класс проблемы, что уже отверг автоматический парсинг
  неструктурированного текста в других ADR этого проекта, принцип 2
  CLAUDE.md: где нужно человеческое суждение о смысле, а не
  механическое правило — вход должен идти через ручной ввод, не через
  эвристику).

## Последствия

- Новая nullable-колонка `suppliers.short_name` (`VARCHAR(50)`),
  Alembic-миграция по образцу `4f2931515181`.
- `SupplierOut`/`SupplierUpdate` получают поле `short_name: str | None`;
  `SupplierCreate` — не получает (форма создания не меняется, п.4).
- `SupplierDetailPage.tsx` (`BasicInfoSection`) — новое поле формы.
- `PriceComparisonPage.tsx` — заголовки колонок обеих таблиц используют
  `short_name ?? supplier_name` с полным именем в `title`-тултипе.
- `docs/data-model.md`: добавить `short_name` в описание `Supplier`.
- Явно не в объёме, зафиксировано как возможное будущее расширение:
  использование `short_name` на других экранах приложения (п.3);
  валидация уникальности сокращений.
- Реализация (миграция, схемы, форма, шапка таблицы, тесты) — предмет
  этой же задачи после принятия ADR.
