# ADR-0040: Текущая активная цена в ревью прайс-листа — подсветка дешевле/дороже

Статус: Принято

## Контекст

`PriceListImportReviewPage` (ADR-0019/ADR-0020) сегодня показывает
распознанную из прайса цену (`PriceListEntry.price`) саму по себе — без
сравнения с тем, что уже было у этого поставщика для этого материала.
Сотрудник, ревьюющий прайс, не видит на экране, подорожала позиция или
подешевела, и вынужден сверять вручную с другим экраном.

Проверено перед решением (см. также вопрос в чате, разобравший все три
пункта фактами из кода):

1. **API ревью не отдаёт текущую активную цену вообще.**
   `_entry_out`/`_to_import_out` (`backend/app/api/price_ingestion.py`)
   строят `PriceListEntryOut` только из колонок `PriceListEntry`, без
   join к `Price`. Ключ для join, дающий осмысленное сравнение — именно
   `(matched_material_id, import.supplier_id)`, а не "любая активная цена
   материала у любого поставщика": пользователь заносит прайс конкретного
   поставщика, сравнение с ценой другого поставщика не отвечает на вопрос
   "этот поставщик поднял/снизил цену". Тот же фильтр
   `Price.valid_to.is_(None)` для активной цены уже используется как
   устоявшийся паттерн в `apply.py`, `order.py`, `price.py`,
   `allocation/service.py` и др.
2. **Единица измерения не может разойтись на этом экране.** `Material.unit`
   — единственная колонка (на `Material`, не на `Price`, не на
   `PriceListEntry`/`ExtractedPriceLine` — там такого поля нет вообще).
   Текущая активная `Price` и новая распознанная строка, когда
   `matched_material_id` заполнен, ссылаются на один и тот же `Material` —
   у сравниваемой пары физически одно значение `unit`, разойтись негде.
   ADR-0036 (порча `Material.unit` ведущим "1 ") — про качество самого
   значения unit, не про два разных unit у сравниваемых величин; проблема
   ортогональна этому экрану.
3. **Валюта — единая (USD) на практике.** ADR-0019 §6 зафиксировал, что все
   реальные прайсы поставщиков компании — в USD (`import_real_data.py`
   хардкодит `currency="USD"`), `Price.currency` имеет `default="USD"`.
   Мультивалютность остаётся открытым вопросом (spec.md §8), но эта ADR
   его не решает и не обязана — сравнение чисел в лоб безопасно для
   сегодняшнего состояния каталога. Фронтенд уже отражает это допущение:
   `formatMoney()` на этом экране хардкодит префикс `$` независимо от
   `entry.currency`.

Итог: пункты 2 и 3 не требуют отдельного решения (структурно невозможно
разойтись по unit; currency сегодня фактически одна) — блокера для
реализации нет, добавляется только недостающее поле из п.1.

## Решение

**Новое вычисляемое поле `PriceListEntryOut.current_active_price:
float | None`** — не колонка БД, не персистентно, вычисляется на каждый
`GET`/`POST`-рендер тем же join'ом, что `apply.py::_apply_match` уже
использует для поиска активной цены при применении строки:

```python
Price.material_id == entry.matched_material_id,
Price.supplier_id == price_list_import.supplier_id,
Price.valid_to.is_(None),
```

`NULL` в двух случаях, оба — не ошибка:
- `matched_material_id IS NULL` — сравнивать не с чем, материала ещё нет.
  После ADR-0025 единственный путь оказаться на экране ревью с
  `matched_material_id == NULL` — строка с `processing_status="failed"`
  (retry исчерпан на матчинге, ADR-0022 §2); настоящего "предложено
  new"-состояния от ИИ на этом экране больше не существует (ADR-0025 §3/§5
  убрала `action="new"` из решений matching и убрала показ `not_found`
  строк вообще). Пользователь всё ещё может вручную решить применить
  такую строку как `action="new"` через `apply` (`ApplyEntryIn` этого не
  запрещает), но это не AI-предложение, значит и сравнивать не с чем в
  любом случае;
- материал сматчен, но для пары (этот поставщик, этот материал) ещё не
  было ни одной `Price` (первая позиция от этого поставщика) — join не
  находит строку.

Оба случая рендерятся на фронтенде как `—`, не как `0`/ошибка —
`current_active_price: null` от бэкенда уже различим от `0`, различать
дальше не нужно: с точки зрения UI оба "нет базы для сравнения".

**Вычисляется не персистентным полем, а на чтении** — в отличие от
`suggested_internal_sku`/`possible_duplicate_of` (ADR-0020), это значение
не одноразовый снимок момента ИИ-анализа, а живое состояние каталога:
если пока строка лежит на ревью, кто-то вручную обновил цену через
`PUT /prices/{id}`, сотрудник должен увидеть актуальное сравнение, а не
цену на момент загрузки файла. Не требует новой колонки/миграции.

**Подсветка на фронтенде** (`PriceListImportReviewPage.tsx`): когда
`current_active_price != null`, распознанная цена (`entry.price`)
красится зелёным при `price < current_active_price` (дешевле) и красным
при `price > current_active_price` (дороже); при равенстве — без
подсветки (нейтрально, не "хорошо" и не "плохо"). Текущая цена
показывается рядом как обычный текст (не подсвечивается сама по себе —
подсветка относится к новой цене относительно неё). Использованы уже
существующие в проекте цветовые токены (`--color-success-alt`/
`--color-danger-text`, тот же словарь, что бейджи confidence на этом же
экране), новых токенов не вводится.

## Альтернативы

**Персистировать `current_active_price` на `PriceListEntry` при создании
импорта** (по аналогии с ADR-0020). Отклонено: в отличие от
`suggested_internal_sku`/`possible_duplicate_of` (черновые ИИ-подсказки,
корректно замороженные на момент анализа), активная цена поставщика —
изменяемый факт каталога, который ревьюер должен видеть свежим при
каждом открытии экрана, а не то, что было верно в момент загрузки файла.

**Сравнивать с любой активной ценой материала у любого поставщика**
(без фильтра по `supplier_id`). Отклонено — не отвечает на вопрос, ради
которого делается подсветка ("этот поставщик подорожал или подешевел"),
подмешивает цены конкурентов, которые могут быть структурно другими
(другие условия доставки/объёма).

## Последствия

- `backend/app/api/schemas/price_ingestion.py` — новое поле
  `PriceListEntryOut.current_active_price: float | None`.
- `backend/app/api/price_ingestion.py` — `_entry_out` получает join к
  активной `Price` по `(matched_material_id, price_list_import.supplier_id)`.
- `frontend/src/api/types.ts` — `PriceListEntry.current_active_price:
  number | null`.
- `frontend/src/routes/price-list-import/PriceListImportReviewPage.tsx` —
  колонка/подпись с текущей ценой и цветовая подсветка распознанной цены.
- Не требует миграции БД — поле не персистентно.
- Тесты: `GET`/`POST` возвращают `current_active_price` для строки с
  существующей активной ценой у этого поставщика; `null` для
  `action="new"`-кандидата и для впервые встреченного у этого поставщика
  материала; ручное обновление цены через `PUT /prices/{id}` между
  загрузкой импорта и повторным `GET` отражается в следующем ответе
  (доказывает "вычисляется на чтении", не снимок).
