# ADR-0054: Матрица цен «все материалы × все поставщики» для администраторов

Статус: Принято (2026-11-12)

## Контекст

До инструмента руководство вело Excel «All materials SFF»: слева материалы по
группам, в столбцах поставщики, в ячейке цена. Цена красилась зелёным, если у
поставщика она стала ниже, чем в прошлой вкладке-снимке, и красным, если выше.
По этой таблице руководство проверяло, обновляет ли сотрудник цены и как они
меняются.

В инструменте история цен уже есть: `Price` версионируется (`valid_from` /
`valid_to`, закрытые строки не удаляются). Но смотреть её можно только точечно:
в ордере (`/orders/{id}/items/{id}/price-history`, одна пара материал +
поставщик ордера) и на сравнении цен внутри проекта (только материалы проекта).
Сводного вида нет.

## Решение

1. **Новый экран `/prices`** (пункт меню «Цены», только `admin`). Это матрица:
   строки — все материалы каталога, сгруппированные по категориям (порядок
   ADR-0042/ADR-0049), столбцы — поставщики, у которых есть хотя бы одна
   активная цена. В ячейке активная цена (`valid_to IS NULL`).

2. **Эндпоинты под существующим admin-роутером `/prices`** (ADR-0024 §4):
   - `GET /prices/matrix?compare_to=YYYY-MM-DD` — матрица целиком;
   - `GET /prices/history?material_id=&supplier_id=` — история пары с
     источником каждой версии.
   Логика вынесена в `app/services/price_matrix.py`. Всё сравнение и все
   итоги считает backend (принцип 4 CLAUDE.md), frontend только фильтрует
   и отображает.

3. **База сравнения — два режима:**
   - по умолчанию (`compare_to` не задан) — **предыдущая версия** цены этой
     пары, когда бы она ни была;
   - `compare_to=D` — цена, действовавшая на дату D: `valid_from <= D` и
     (`valid_to IS NULL` или `valid_to > D`). Это аналог сравнения двух
     вкладок Excel.
   Результат по ячейке: `down` / `up` / `same` / `new` (базы нет — цена
   появилась позже) и `change_pct`, если база не 0.

4. **Контроль актуальности по поставщику:** `last_price_date` — максимальный
   `valid_from` среди всех цен поставщика; `days_since_update` и `is_stale`
   (порог `STALE_AFTER_DAYS = 30`), плюс счётчики `up/down/new` в выбранном
   сравнении. Те же счётчики есть в общей сводке.

5. **Самая дешёвая цена в строке** (`is_cheapest`) — при двух и более
   активных ценах, все равные минимуму. Валюту не сравниваем: справочник
   сейчас целиком в USD.

6. **Источник версии в истории** определяется без миграции:
   - `source_order_item_id` задан → `order` (ADR-0030, автор
     `created_by_user_id`);
   - иначе `source_import_id` задан и **отличается от предыдущей версии** →
     `import`. `version_price()` наследует `source_import_id` от закрываемой
     строки, поэтому одинаковый id у соседних версий означает не новый импорт,
     а ручную правку поверх него;
   - иначе → `manual` (admin `/prices`, `sync_catalog_from_file`).

## Альтернативы

- **Календарное сравнение «этот месяц vs прошлый».** Отклонено: обновления
  неравномерны, и у поставщика, обновлённого дважды за месяц, первое изменение
  «пропадёт». Сравнение с произвольной датой это покрывает.
- **Хранить снимки матрицы (как вкладки Excel).** Отклонено: история уже есть
  в `Price`, снимок по дате восстанавливается запросом.
- **Колонка `source` в `Price`.** Точнее для будущих записей, но требует
  миграции и не помогает старым данным. Отложено: вывод из п.6 корректен для
  всех текущих путей записи.

## Последствия

- Маршруты `/prices/matrix` и `/prices/history` объявлены до
  `/prices/{price_id}`, иначе FastAPI отдаст 422 на разборе UUID.
- Для импорта автор неизвестен: у `PriceListImport` нет поля «кто загрузил».
  В истории показывается дата импорта без автора.
- Порог «давно не обновлялся» (30 дней) — константа, не настройка. Сменить
  его можно правкой константы, без нового ADR.
