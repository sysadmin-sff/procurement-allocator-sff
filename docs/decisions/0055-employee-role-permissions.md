# ADR-0055: Права сотрудника — проекты, поставщики, материалы, шаблоны

Статус: Принято (2026-11-13). Заменяет permission-матрицу ADR-0024 §4 в
части `supplier`, `material`, `category`, `price`, `price_ingestion`,
`template`; заменяет ADR-0051 §2 в части грантов на «Замеры».

## Контекст

По ADR-0024 §4 сотрудник (`employee`) вёл только проекты, расчёт и ордера,
а все справочники были `admin`-only. На практике закупками занимаются
сотрудники: им нужно заводить поставщиков, загружать прайс-листы, править
материалы и шаблоны без админа. Руководству при этом нужно оставить за собой
контроль цен (матрица ADR-0054), справочник категорий, пользователей и
«Замеры».

## Решение

Permission-матрица по роутерам (механизм прежний — router-level
`dependencies`, ADR-0024 §5):

| Роутер | Доступ |
|---|---|
| `project`, `allocation`, `order`, `purchase_record` | любая роль (без изменений) |
| `supplier` (вкл. офисы, контакты, удаление алиасов ответа) | **любая роль** |
| `material` | **любая роль** |
| `price` — CRUD `/prices` | **любая роль**: правка цен в карточке материала |
| `price_matrix` — `/prices/matrix`, `/prices/history` | `admin` (новый файл `app/api/price_matrix.py`) |
| `price_ingestion` — загрузка, ревью, применение прайса | **любая роль** |
| `template` | **любая роль**, включая создание и правку |
| `category` — `GET /categories` | **любая роль**: список нужен форме материала |
| `category` — POST/PATCH/DELETE | `admin` (отдельный `admin_router` в том же файле) |
| `user` | `admin` (без изменений) |
| `measurements` | **только `admin`** |

Подробности:

1. **`/prices` разделён на два роутера.** CRUD остаётся в `price.py` под
   `get_current_user`, матрица и история уходят в `price_matrix.py` под
   `require_role("admin")`. `price_matrix` подключается в `main.py` до
   `price`: иначе `/prices/matrix` уходит в `/prices/{price_id}` и даёт 422.
2. **`/categories` — два роутера с одним префиксом:** чтение для всех,
   изменение для admin. Пересечения путей нет, методы разные.
3. **«Замеры» только для admin.** `require_measurements_access` больше не
   смотрит в `measurements_user_access`. Таблица и
   `app.measurements.scripts.grant_access` не удалены: решение можно
   откатить без миграции, но выданные гранты сейчас ничего не открывают.
4. **Frontend.** Меню сотрудника: Проекты, Поставщики, Материалы, Шаблоны.
   Админ дополнительно видит Цены, Категории, Пользователи и Замеры.
   Блокировки кнопок по роли (`isAdmin`) сняты на страницах материалов,
   поставщиков, шаблонов и ревью импорта. `/prices`, `/categories`, `/users`
   обёрнуты в `RequireAdmin`: сотрудника, открывшего адрес напрямую, ведёт
   на `/projects`. «Замеры» не обёрнуты: при 403 они сами показывают «Нет
   доступа к разделу» (ui-reference §9). Как и раньше, frontend — удобство,
   а граница прав проходит на backend.

## Альтернативы

- **Разделить импорт прайса на «загрузить» (все) и «применить» (admin)** —
  риск, отложенный в ADR-0024 §4. Отклонено: решили, что сотрудник проводит
  импорт целиком.
- **Отдельная роль «менеджер закупок»** — избыточно: ролей по-прежнему две.

## Последствия

- Любой сотрудник может менять боевые цены: через карточку материала, через
  импорт прайса и через подтверждение цен в ордере (ADR-0030). Контроль —
  матрица цен и история с источником каждой версии (ADR-0054), только у
  admin.
- Новый роутер по-прежнему обязан явно попасть в одну из категорий этой
  таблицы до мержа (правило ADR-0024 §4).
