# ADR-0058: Ежедневный отчёт по замерам для отчётного бота

Статус: Принято (2026-11-20)

## Контекст

Метрики замеров (ADR-0053) смотрят в инструменте админы. Владельцы компании
каждый день получают общую сводку от отчётного Telegram-бота (`daily-bot`,
отдельный Node.js-сервис с MongoDB): в 8:40 по Нью-Йорку бот рассылает PDF
пользователям с должностью «Owner». Туда нужно добавить замеры: сколько
проведено за вчера по замерщикам и итог с начала месяца.

Весь доступ к API сейчас — сессия после входа через Google (ADR-0024), у бота
её нет.

## Решение

1. **Данные считает procurement-allocator, бот только форматирует.** Функция
   `daily_report()` (`app/measurements/daily_report.py`) переиспользует
   выборку и правила подсчёта страницы «Замеры» (`metrics._rows_cte`,
   `metrics._counts`): «проведено» значит ровно то же, что
   `conducted.total` в `/measurements/metrics`. Отдаётся:
   - `date` — отчётный день (по умолчанию вчера по Нью-Йорку);
   - `day` — проведено за этот день: всего и по замерщикам;
   - `month` — с 1-го числа месяца отчётного дня по этот день включительно:
     всего и по замерщикам. 1-го числа это полный прошлый месяц;
   - `data_as_of` — когда данные последний раз успешно читались из amoCRM.
   Замерщики — объединение тех, у кого есть строки за месяц; ключ `null` —
   визит без сопоставленного замерщика.

2. **Машинный доступ по токену, отдельный путь.**
   `GET /integrations/measurements/daily-report?date=YYYY-MM-DD` с заголовком
   `Authorization: Bearer <MEASUREMENTS_REPORT_TOKEN>`.
   - Токен — переменная окружения backend; сравнение `hmac.compare_digest`.
   - Токен не задан → 404 (интеграция выключена), неверный или отсутствующий
     заголовок → 401. Дата в будущем → 422.
   - Маршрут существует только при `MEASUREMENTS_ENABLED=true`, как и весь
     модуль.
   - Путь вне `/measurements`: правило «каждый маршрут `/measurements` закрыт
     `require_measurements_access`» (сессия admin, ADR-0055) остаётся без
     исключений. Токен открывает только этот отчёт: никаких лидов, адресов,
     текстов — только имена замерщиков и количества.

3. **Бот** (`daily-bot/bot/main.js`) после общего PDF владельцам запрашивает
   отчёт и отправляет его владельцам отдельным текстовым сообщением. Блок
   уходит независимо от того, сформировался ли PDF: сводка пропускается в
   дни, когда никто не сдал отчёт, а замеры нужны каждый день. Ошибка запроса
   логируется и не мешает остальной рассылке. Команда `/zamery` (админ или
   владелец) присылает тот же блок только себе — для проверки.

## Альтернативы

- **Бот читает Postgres напрямую.** Отклонено: правила «проведено»
  (дубликаты, исходы, отказ до визита) пришлось бы повторить в JS, и цифры
  разошлись бы со страницей «Замеры».
- **Сервисный пользователь с сессией.** Отклонено: сессии живут ограниченное
  время и привязаны к входу через Google; бот должен работать без
  вмешательства.
- **Расширить `require_measurements_access` токеном.** Отклонено: токен
  открыл бы весь модуль, включая списки визитов.

## Последствия

- На сервере procurement-allocator нужна переменная
  `MEASUREMENTS_REPORT_TOKEN`, у бота — тот же токен и адрес backend
  (`MEASUREMENTS_REPORT_URL`, `MEASUREMENTS_REPORT_TOKEN`).
- Смена правил подсчёта на странице «Замеры» автоматически меняет и отчёт
  бота — это намеренно.
