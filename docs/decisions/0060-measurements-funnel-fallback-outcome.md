# ADR-0060: Исход замера по воронке, если Site Visit Result не заполнен

Статус: Принято (2026-11-23). Дополняет ADR-0053 §1–§3.

## Контекст

По ADR-0053 исход замера со сроком после `cutover_at` (09.11.2026) берётся
только из поля сделки Site Visit Result. Воронка для таких замеров не
смотрится. На практике поле часто не заполняют: у свежих замеров исход
пустой, а выполненный замер без результата считается проведённым, даже
если сделку после него вернули в Квалификацию. Для замеров до `cutover_at` есть
правила по воронке (ADR-0053 §3), и они работают.

## Решение

1. **Порядок исхода для `site_visit`:**
   1. действующий Site Visit Result группы — как раньше;
   2. если его нет — исход по воронке по правилам §3 ADR-0053 (окно, выход из
      Measurements, `produced` / `closed` / `not_held` / `no_data`);
   3. по воронке тоже нечего взять — `no_data`.
   `result_source` остаётся `site_visit`. Запасной исход хранится в тех же
   колонках `funnel_outcome`, `no_data_reason`, `funnel_exit_event_id`; при
   заполненном поле они `NULL`. Схема БД не меняется.
2. **M1 (проведённые) для `site_visit`:** результат есть — проведён, если он
   не `declined`; результата нет — проведён, если запасной исход не
   `not_held`. То же условие в M2: `not_held` по воронке не считается
   запланированным.
3. **M6 не меняется:** `without_site_visit_result` по-прежнему считает
   прошедшие группы `site_visit` без действующего результата, в том числе с
   запасным исходом. Иначе пропадёт сигнал, что поле не заполняют.
4. **Список визитов:** `outcome` — сначала Site Visit Result, затем воронка.
   Новое поле `outcome_by_funnel` (`true`, если поле пустое и исход взят из
   воронки). На экране к такому исходу добавляется «· по воронке».
5. **Версия правил исходов** `OUTCOME_RULE_VERSION` 2 → 3. Существующие строки
   становятся устаревшими (`outcomes_stale` > 0) до пересчёта
   `python -m app.measurements.scripts.recompute --apply`. Пересчёт читает
   только нашу БД, amoCRM не трогает.

## Альтернативы

- **Только показывать запасной исход, не меняя M1.** Отклонено владельцем:
  замер, после которого сделку вернули в Квалификацию, не должен считаться
  проведённым только потому, что не заполнили поле.
- **Заменить Site Visit Result воронкой полностью.** Отклонено: поле —
  прямое свидетельство замерщика и точнее воронки, когда заполнено.

## Последствия

- После выкатки до пересчёта страница «Замеры» показывает предупреждение об
  устаревших исходах; цифры меняются после `recompute --apply`.
- «Проведено» за ноябрь может уменьшиться на замеры без результата, сделки
  которых вернули в Квалификацию. Ежедневный отчёт бота (ADR-0058) считается
  по тем же правилам и изменится так же.
