# UI Reference — поведенческая логика экранов

Этот файл описывает КАК себя ведут экраны. КАК они выглядят — в `docs/design/*.html`.
Заполняется/уточняется после каждой генерации в Claude Design и показа пользователям.

## 1. Ревью прайс-листа (`docs/design/01-price-review.html`)

- Строки сортируются по возрастанию confidence (низкая уверенность — наверх).
- Пороги confidence: `>90%` — зелёный, `70–90%` — жёлтый, `<70%` — красный.
- Дельта цены к предыдущей: подсвечивается красным, если рост `>20%` — требует
  осознанного подтверждения, не должно быть "проскроллено мимо".
- Массовое одобрение — только для строк с confidence `>95%`; остальные — построчно.
- Ничего не пишется в `Price` до нажатия "Применить одобренные".
- [ ] уточнить после первого показа пользователю: нужен ли предпросмотр PDF-страницы
      в панели рядом со строкой, или это редко используется.

## 2. Конструктор проекта (`docs/design/02-project-builder.html`)

- Поиск по материалу: минимум 2 символа до появления результатов, показывает
  категорию материала рядом с названием.
- Enter в последней строке таблицы добавляет новую пустую строку.
- Единица измерения подставляется автоматически при выборе материала (readonly).
- Кнопка "Рассчитать закупку" неактивна, если хотя бы одна строка не заполнена
  полностью (материал + количество).
- [ ] уточнить: что происходит при добавлении одного и того же материала дважды —
      сливать строки или разрешать дублирование.

## 3. Результат распределения (`docs/design/03-allocation-result.html`)

- Бейдж "не самая дешёвая цена" показывается для каждой строки, где алгоритм выбрал
  не минимальную цену за единицу; текст объяснения: разница в цене vs. экономия на
  консолидации доставки, в долларах.
- Предупреждение о нехватке материала — красный блок, не скрывается по умолчанию,
  не в конце страницы, а на уровне соответствующей позиции.
- Ручное переопределение поставщика — select прямо в строке; после изменения
  показывается индикатор "изменено вручную" (отдельно от бейджа "не самая
  дешёвая цена" — оба могут быть показаны одновременно, см. ADR-0006), а
  backend пересчитывает и возвращает обновлённые сводки поставщиков (старого
  и нового) — не клиентская арифметика, см. ADR-0006 п.4 (обоснование: money
  math — backend-only, CLAUDE.md принцип 4).
- Переопределение разрешено даже если у нового поставщика явно недостаточное
  `availability` на материал — не блокируется, но строка получает отдельный
  видимый признак риска (не путать с индикатором "изменено вручную"). См.
  ADR-0006 п.2. Реализовано в `AllocationResultPage.tsx` (`LineRow`) как
  отдельная строка текста под ячейкой материала (не бейдж — `display: block`,
  класс `.availabilityRisk`), цвет `--color-danger-text`, видимый текст, не
  `title`-тултип (тот же стандарт, что и для остальных индикаторов строки, см.
  ниже). Текст: "⚠ у поставщика доступно {availability} {unit}, требуется
  {quantity}". Условие показа не привязано к самому факту override — это
  сравнение `Price.availability` **текущего** поставщика строки (кто бы его ни
  назначил, солвер или ручной override) с `line.quantity`, показывается только
  когда `availability` явно задан (не `null`) и меньше требуемого количества —
  симметрично тому, как ADR-0005 трактует `availability IS NULL` как "не
  проверялось", а не как риск.
- Предупреждение о недостижении минимальной суммы заказа поставщика
  (`below_min_order`, возникает как побочный эффект переноса позиции между
  поставщиками) — отдельная текстовая строка **под** заголовком карточки
  поставщика (между именем/доставкой/итогом и таблицей строк), на всю
  ширину карточки, в цвете `--color-danger-text`, без блочного padding
  уровня `warningBlock` (это контекст одной карточки, не событие уровня
  страницы). Текст: "⚠ Сумма заказа {goods_total} меньше минимальной
  {per_order_min_amount} — поставщик может отклонить заказ." Не блокирует
  PATCH переопределения. См. ADR-0006 п.4 за обоснованием, почему не бейдж
  в хедере карточки и не изменение цвета итоговой суммы.
- Кнопка "Подтвердить и создать ордера" — финальный шаг, необратимый (создаёт `Order`).
  Генерация должна читать текущее (с учётом override) состояние
  `AllocationLine`, не исходный результат ILP-расчёта — см. ADR-0006 п.6.
- Повторный запуск ILP с "заморозкой" переопределённой позиции — не в
  объёме; ручное правило — это override, который фиксируется поверх текущего
  состояния строки без пересчёта остального проекта. См. ADR-0006
  "Альтернативы".
